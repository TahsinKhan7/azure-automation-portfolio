## 5. Deployment steps

1. Pipeline `arm-validate-deploy` publishes Template Spec version `{{RELEASE_ID}}` into the environment's template spec resource group.
2. Validation and what-if run automatically; the what-if Markdown is attached to the build summary and published as the `whatif-{{TARGET_ENVIRONMENT}}` artefact.
3. Approvers release the `{{TARGET_ENVIRONMENT}}` environment check in Azure DevOps (prod also completes the manual validation task).
4. `az deployment group create` runs with `--mode Incremental` against `{{RESOURCE_GROUP}}`; deployment name `dp-{{TARGET_ENVIRONMENT}}-<buildId>`.
5. Deployment outputs are published as the `deployment-outputs-{{TARGET_ENVIRONMENT}}` artefact.

## 7. Rollback plan

ARM deployments are incremental, so rollback means redeploying the previous known-good Template Spec version rather than deleting resources.

1. Identify the previous version: `az ts show -g <templateSpecRg> -n dataplatform-landing-zone --query "versions"` or the last successful pipeline run.
2. Re-run the pipeline for that commit with `deployThroughTo` set to `{{TARGET_ENVIRONMENT}}`, or deploy directly:
   `az deployment group create -g {{RESOURCE_GROUP}} --template-spec <previousVersionId> --parameters @{{PARAMETER_FILE}}`
3. Properties that cannot be reverted by redeployment (purge protection, soft-delete retention, HNS) are called out in the what-if review and need a forward fix instead.
4. Record the rollback and root cause on the change record.
